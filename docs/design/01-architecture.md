# 架构说明

## 分层

```
cmd/scherun            命令行入口: 参数解析, 版本打印, 路径打印
internal/app           装配层: 按顺序初始化各组件, 统一退出
internal/appdirs       目录解析, 支持环境变量覆盖
internal/config        配置读写与版本迁移
internal/logging       slog 多输出与轮转清理
internal/envimport     从登录 shell 读取环境变量, 多层合并
internal/store         SQLite 打开, 迁移, 任务 DAO
internal/task          任务模型与触发方式
internal/proc          子进程启动与终止 (平台相关)
internal/scheduler     调度器, 每任务 guard, 状态与告警
internal/single        按数据目录绑定的单实例锁
internal/localapi      本地 HTTP: 鉴权, REST, SSE, 静态资源
internal/tray          托盘图标与菜单, macOS Dock 隐藏
internal/webui         内嵌前端资源
web/                   React 前端工程
```

依赖方向单一: `app` 依赖其余模块, 业务模块之间只依赖 `task`, `store`, `proc` 这些底层包,
没有循环依赖.

## 启动顺序

1. 解析目录, 读取配置 (损坏时退化并备份).
2. 初始化日志: 终端与轮转文件双输出.
3. 获取单实例锁; 拿不到锁说明已有实例, 转发打开请求后退出.
4. 打开数据库并执行迁移.
5. 启动调度器, 为每个任务建立 guard 协程.
6. 启动本地 HTTP 服务, 写入 `runtime.json`.
7. 创建托盘, 进入托盘事件循环 (占用主 goroutine).
8. 按配置决定是否自动打开浏览器.

## 退出顺序

所有退出入口 (托盘退出, 界面退出, SIGINT/SIGTERM) 都汇入同一个函数, 顺序固定:

1. 停止调度器: 取消全部 guard, 逐个停止任务进程, 等它退出.
2. 关闭 HTTP 服务并删除 `runtime.json`.
3. 刷盘并关闭日志.
4. 释放单实例锁.

## 调度模型

调度器本身不持有全局锁来做调度决策, 每个任务一个 guard 协程:

- guard 内是一个 `select` 循环, 同时监听: 取消信号, 手动指令通道, 定时 ticker,
  定时一次信号, 进程退出通道.
- 进程退出由 `proc.Process` 内部的单一等待协程完成, 结果缓存在通道里,
  因此 `Wait` 可以重复调用而不会触发 `exec.Cmd` 的重复等待错误.
- 停止任务时只发信号, 退出后的状态更新与重启决策仍走退出通道, 保证状态不会残留.

触发方式的实现:

| 方式 | 行为 |
| --- | --- |
| Manual | 只在收到手动指令时运行 |
| Startup | 应用启动时运行一次 |
| KeepAlive | 启动时运行, 退出后立即重启, 连续失败触发挂起 |
| Routine | 按固定间隔运行, 上一次还在跑时跳过本次 |
| Instant | 到达指定时刻运行一次, 已跑过则不重复 |
| UntilSucceed | 启动时运行, 退出码非 0 就继续重试 |

### 用户暂停

KeepAlive, Routine, UntilSucceed 这三种会自动拉起进程, 停止按钮对它们不能只发信号:
进程退出后调度循环会立刻把它重新启动, 用户看到的只是几十毫秒的空闲. 因此 guard
额外持有一个 `pausedByUser` 标记:

- 收到停止指令时先置标记再发信号. 顺序不能反, 否则退出分支先跑, 会认为用户没按过停止.
- 退出处理先看标记, 自动重启类任务直接返回, 状态置为 `paused`.
- 手动运行清除标记, 状态回到 `running`, 自动触发随之恢复.
- Routine 的 ticker 在暂停期间跳过触发, 不会因为到点就绕过暂停.

`paused` 与 `disabled` 是两种不同的东西: 前者是本次运行的临时意愿, 点运行即恢复,
不写回任务定义; 后者是任务级配置, 持久化到数据库, 重启应用后依然生效.
`paused` 也不等同于 `suspended`: 后者表示连续失败后系统主动刹车, 会附带一条告警,
前者只是用户按了停止, 不应产生失败告警.

## 进程管理

- unix: `setpgid` 让任务独占进程组. 停止时向 `-pid` 发 SIGINT,
  5 秒未退出再对整组 SIGKILL, 保证任务派生的子进程一起结束.
- windows: `no_console` 时以 `CREATE_NO_WINDOW` 启动并把标准流置空
  (GUI 程序没有可继承句柄, 保留继承会导致启动失败), 停止用终止进程.
- macOS 的 `.app` 目录经 `open -a` 启动, 此时无法重定向标准流, 退出码也不反映应用自身状态.

## 失败处理

| 情况 | 处理 |
| --- | --- |
| 端口被占用 | 启动失败并提示修改 `local_bind`, 不静默换端口 |
| 数据库打开或迁移失败 | 报可读错误并退出, 保留现场, 不自动删库 |
| 配置解析失败 | 备份为 `.broken`, 用默认值继续并记 warn |
| 程序不可执行 | 界面标注, 启动失败进告警队列 |
| 任务无限重启 | 3 秒内失败 6 次即挂起该任务的自动触发 |
| 停止超时 | SIGINT 5 秒后强杀, 记告警 |
